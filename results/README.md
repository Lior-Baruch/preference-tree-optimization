# Results

The numbers behind the main README: two PTO runs that differ only in look-ahead depth
(K = 0 and K = 5), each trained for 10 iterations and evaluated by two LLM judges.

## Setup

| | |
|---|---|
| Policy | `meta-llama/Llama-3.2-1B` + LoRA (r = 16), DPO |
| Patient simulator and training oracle | `gpt-4o-mini-2024-07-18` |
| Training reward | mean of the Q1 and Q2 questionnaires (1–5) |
| Tree | greedy, M = 8 branches, τ = 0.1, MCL = 12, conversations of up to 50 utterances (the therapist's opening line plus 49) |
| Runs | `configs/pto_k0.yaml` and `configs/pto_k5.yaml`, seed 42, one run each |
| Evaluation set | the 96 conversations (one per persona) generated by each model state |

**Iterations.** Iteration *n* is the policy after *n* DPO updates; iteration 0 is the base model.
Each arm draws its own iteration-0 conversations, so the two arms have two independent samples of
the base model (they agree within noise).

**Judges.** Every conversation was scored by

- the **training judge** `gpt-4o-mini-2024-07-18` (temperature 0.1, seed 42, strict JSON schema),
  the same model that served as the training oracle, and
- a **held-out judge** `claude-haiku-4-5`, which never influenced training.

The held-out judge is systematically stricter, so compare *trends and contrasts* across judges,
never absolute levels.

**Instruments** (one judge call per conversation each; `pto evaluate` reproduces them):

| Instrument | Range | Meaning |
|---|---|---|
| Q1+Q2 | 1–5 | mean of Q1 (session satisfaction, 5 items) and Q2 (working alliance / relational communication, 17 items); the training reward |
| Q1, Q2 | 1–5 | the two halves of the reward |
| WAI-SR | 1–5 | Working Alliance Inventory, short revised (goal, task, bond) |
| CSQ-8 | 1–4 | Client Satisfaction Questionnaire |
| MI-SAT | 1–5 | satisfaction with the motivational-interviewing intervention |
| MITI | 1–5 | mean of the MITI global ratings (MI treatment integrity) |
| PCT | 0–1 | patient change talk: CT / (CT + ST) over the patient utterances coded by the MI process coder; undefined when the coder found neither, so `n` can be below 96 |
| MICI | ≥ 0 | MI-inconsistent therapist behaviours per therapist turn; **lower is better** |

**Statistics.** All contrasts are paired by persona (the same 96 personas in every model state).
`d_z` is the mean paired difference divided by its standard deviation; `ci_low` / `ci_high` are
persona-bootstrap 95% intervals; `p_wilcoxon` is the Wilcoxon signed-rank test; Holm corrections
are applied within the family named in each column. Values are rounded to three decimals as in the
source tables, so a p-value of `0.000` means p < 0.0005.

## Files

All CSVs in [`data/`](data/) were parsed programmatically from the tracked result tables of the
thesis analysis (repository commit `1daedb5`, results directory `eda/results/`), keeping only
the PTO rows; no number was typed by hand. Source paths below are relative to that directory.
Arm labels `PTO_LA0` / `PTO_LA5` in the sources are `k = 0` / `k = 5` here.

### `k_contrast_by_iteration.csv`

K = 0 vs K = 5, every instrument at every iteration 0–10, both judges (198 rows). Drives panel (a)
and the MICI panels of the results figure.

| Column | Meaning |
|---|---|
| `judge`, `instrument`, `iteration`, `n` | cell identity; `n` = personas with both values |
| `mean_K0`, `mean_K5`, `se_K0`, `se_K5` | arm mean and standard error over personas |
| `delta_K0_minus_K5`, `d_z`, `ci_lo`, `ci_hi` | paired contrast, **sign K=0 − K=5** |
| `p_wilcoxon`, `p_holm_across_iterations` | Holm across iterations 0–10 within (judge, instrument) |
| `lower_is_better` | `True` for MICI |

Sources: `lookahead/reward/tables/k_paired_pto_gpt-4o-mini.md`,
`lookahead/reward/tables/k_paired_pto_claude-haiku-4-5.md` (bootstrap seed 12345).

### `k5_vs_k0_iter10.csv`

The look-ahead effect at the last iteration: K = 5 vs K = 0 at iteration 10, per instrument and
judge (**sign K=5 − K=0**; on MICI a negative value favours K = 5). `p_holm_across_instruments`
corrects across the nine instruments within a judge; this is the family quoted in the main
README. (`k_contrast_by_iteration.csv` holds the same contrast with the opposite sign and a
different Holm family, so its p_holm differs.)

Source: `lookahead/reward/tables/k_endpoints.md`, pair `PTO_LA5_I10 − PTO_LA0_I10`.

### `pto_vs_base.csv`

Each arm at iteration 10 vs its own base model (iteration 0), per instrument and judge.
`delta_vs_base` = iteration 10 − base (on MICI, positive is worse); `effect` is the conventional
label for |d_z|; `p_holm_across_instruments` corrects across the nine instruments within
(judge, arm); `traj_rho` / `traj_slope` are the Spearman correlation and OLS slope of the
instrument over iterations (descriptive, no test).

Sources: `arms/stats/tables/gpt-4o-mini/main_results.md`,
`arms/stats/tables/claude-haiku-4-5/main_results.md` (rows with `target = final`).

### `overpraise_by_iteration.csv`

Over-praise by iteration for each arm.

- `lexical_overpraise_rate`: share of therapist turns matching an effusive-praise regular
  expression (for example "proud of you", "you got this", "beacon"), averaged over conversations.
  Judge-free and fully reproducible, but brittle: treat it as a directional check.
- `mici_overpraise_rate_<judge>`: the over-praise rate coded by each judge within MICI. Over
  the 22 (arm, iteration) points in this table, it tracks the regex closely (Spearman ρ ≈ 0.86
  for gpt-4o-mini and 0.91 for claude-haiku-4-5, computed from the rounded values in this CSV).

Sources: `arms/validity/tables/gpt-4o-mini/overpraise_crosscheck.md`,
`arms/validity/tables/claude-haiku-4-5/overpraise_crosscheck.md` (the regex column is identical
in both).

### `scorecard.csv`

Iteration-10 means of every instrument for both arms and judges, plus four process measures
derived from the judges' MITI and MI-process codes (`MIPROC_complex_reflection_rate`,
`MITI_reflection_to_question`, `MITI_complex_reflection_share`, `MITI_mi_consistent_share`).
These four come from the thesis analysis code and are not produced by `pto evaluate`.

Sources: `arms/outcomes/tables/gpt-4o-mini/leaderboard_scorecard.md`,
`arms/outcomes/tables/claude-haiku-4-5/leaderboard_scorecard.md` (rows with `target = final`).

### `compute_gpu_hours.csv`

GPU-hours per run (Colab A100), split into conversation generation (`gen_h`), preference-tree
building including look-ahead and oracle scoring (`build_h`) and DPO training (`train_h`).
Hours are wall-clock time on the training host, which includes the API latency the GPU waits
through; they were reconstructed from artifact timestamps because resumed iterations under-record
their own timers. `n_imputed` counts intervals replaced by the phase median (resume gaps);
`total_gpu_h_floor` is an alternative total that credits generation with the larger of the
timestamp span and the recorded generation time (the span misses the first batch).

Source: `compute/cost/tables/compute_by_arm.md`.

### `api_calls.csv`

API calls of the two runs and their K=5 / K=0 ratio, over iterations 1–5 and over all 10 training
iterations: oracle calls, oracle input size (millions of characters), patient calls (total and the
look-ahead "tail"), and candidates scored. `total_api_calls` = oracle + patient calls. Calls made
afterwards by the evaluation judges are not included.

Source: `compute/cost/tables/api_ratio.md`.
